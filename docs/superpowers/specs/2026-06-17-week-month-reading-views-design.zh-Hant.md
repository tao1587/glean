# 週/月閱讀視圖 — 設計

> 英文正本:[2026-06-17-week-month-reading-views-design.md](./2026-06-17-week-month-reading-views-design.md)

**日期:** 2026-06-17
**狀態:** 草稿(待使用者覆核)
**修訂:** 2026-06-17 — 在 v1 加入可選、非破壞性的偏好**排序**。
**範圍:** 閱讀視圖 — `frontend/apps/web/src/pages/reader/shared`(複用 `DigestView`、`TodayBoard` 元件與 `todayBoard.ts` 工具);後端文章列表、一個新的「隱藏」逐篇狀態,以及一個復活的最小偏好評分。

## 概述

目前閱讀器的首頁是一個**以「天」為單位**的版面(digest-today 視圖)。它的侷限是結構性的:要看今天以外的內容,只能**一天一天地切換**,所以跨好幾天回看就得反覆切換 —— 好文章也在這些縫隙裡悄悄溜走。

這份設計要解的需求**不是**清積壓,**也不是**生產力指標,而是「**一張別讓好內容被漏掉的安全網**」。這個定位主導了底下所有決策:

- **排序可以用模型,過濾不行。** 這是核心安全線。一個偏好**評分**(由你自己的「讀 / 儲存 / 隱藏」訊號建出)可以**重新排序**文章 —— 這是非破壞性的,評分不準也只是改變*順序*,絕不藏起任何內容。**隱藏/過濾一律人工、顯式。** 因此不準確永遠擋不住你的閱讀。
- **不用施壓指標。** 未讀計數與進度條會把閱讀框成 KPI(「38 篇未讀,快去清」),製造虛假成就感與壓力,刻意不出現。
- **未讀全部攤開。** 週/月視圖把**所有**未讀文章鋪出來,往下捲就好。不藏在「顯示更多」、分頁點擊,或折疊的「+N 個來源」後面。排序只改順序,不改成員。
- **噪音由你修剪。** 一鍵**隱藏**移除你不在意的內容(經典例子:Claude News 這個源有用,但它那條「我們要在都柏林開辦公室」就沒用)。久而久之留下來的,就是你真正想看的。
- **閱讀本身就是興趣訊號。** 打開並閱讀一篇是正向訊號:讀過的文章**沉**進該來源的「看過的」盒子,*同時*「讀 / 儲存」也餵給偏好評分。沒有額外的「感興趣」按鈕。

週與月是**同一個視圖**的兩個日期範圍。既有的每日視圖維持不變;週/月只是 `日 / 週 / 月` 切換器上新增的兩個選項。

## 目標

- 在既有每日首頁旁,透過 `日 / 週 / 月` 切換器加上一個上/下一期步進按鈕,新增**週**與**月**視圖。
- **以訂閱來源分組的卡片版面**:每張卡片 = 標題、**自身的摘要原文摘錄**(來源描述,非 AI)、時間戳,以及兩個動作 —— **隱藏**與**儲存**。
- **一鍵隱藏**(不感興趣)並可**撤銷**,逐篇持久化。
- **所有未讀靠捲動可見**;已讀依來源折疊;**任何地方都沒有計數**。
- 一個**可選、非破壞性的「按興趣」排序**,由你的「讀 / 儲存 / 隱藏」訊號驅動。預設排序是**時間**;「按興趣」只重排、且永遠一鍵可還原 —— 它不隱藏、不過濾。

## 非目標(明確排除)

- 在這些視圖中做 AI/LLM **摘要或主題聚類**。
- 用**任何模型輸出去隱藏、過濾或移除**內容。模型只能**重排**(排序),不能做減法。
- 從隱藏「學習」去**自動隱藏**類似內容。隱藏可影響**排序**,絕不影響**隱藏**本身。
- 未讀計數、進度指示,或成就/連續打卡式框架。
- 對每個來源做數量上限,或用「點擊展開」才顯示未讀。
- 任何對既有每日(digest-today)首頁行為的更動。

## 已鎖定的決策

| 主題 | 決策 |
|---|---|
| 新增視圖 | **週**與**月**,共用同一個元件;**日** = 現在的 digest-today 首頁,**維持不變** |
| 導覽 | `日 / 週 / 月` 分段切換器 + 上/下一期步進 |
| 主要分組 | **依訂閱來源**(不按天);每張卡片各自顯示日期 |
| 文章卡片 | 標題 + **自身摘要摘錄**(來源描述,2 行截斷)+ 時間戳 + 隱藏 + 儲存 |
| 未讀呈現 | **全部未讀都顯示**,可捲動;不設上限、無「顯示更多」、無分頁點擊 |
| 計數 / 指標 | **一律沒有** —— 沒有未讀計數、沒有進度、沒有已讀數量標籤 |
| 已讀文章 | 沉入每個來源的**「看過的」**折疊盒子(無數字);可展開回看 |
| 隱藏(不感興趣) | **隱藏這一篇**,可**撤銷**;一次性,隱藏行為**不學習 / 不連帶** |
| 儲存 | 複用既有 **`read_later`** |
| 興趣訊號 | **閱讀**該篇(複用自動標記已讀);不設按鈕;閱讀同時餵給評分 |
| **排序** | 非破壞性控制:**時間(預設)** ↔ **按興趣**;排序**絕不隱藏/過濾**,永遠可還原 |
| **偏好評分** | `similarity(文章 embedding, 逐使用者偏好向量)`;復活**最小**版的已移除 M3 基建,**僅用於排序** |
| **訊號 → 評分** | 讀 + 儲存 = **正向**;隱藏 = **負向** |
| **冷啟動** | 「按興趣」優雅降級為時間 / 來源親和度;「時間」為預設,空模型永不擋住視圖 |
| **M3 復活風險** | 先前的偏好系統建過又被移除;依決策我們**不**先追究原因 —— 已接受的風險,靠「只排序 + 可還原」框架收斂 |
| 月視圖密度 | 同一個視圖;**所有未讀攤開**;密度靠已讀下沉 + 隱藏(+ 可選排序)控制 |

## 入口與導覽

- 視圖頂部放一個 `日 / 週 / 月` 分段控制。
  - **日** → 現在的 digest-today 首頁,行為不動。
  - **週 / 月** → 新的彙整視圖,範圍分別是週 / 月。
- 步進按鈕以一週 / 一個月為單位移動錨點。
- URL 狀態沿用 `useReaderController`(`?view=` + 錨點 `?date=`);新增 `view=week` / `view=month`(並可選一個 `sort=` 參數)。複用 `todayBoard.ts` 的週起始(週一)與範圍工具。

## 視圖結構(週與月共用一個元件)

- **頂部欄** —— 期間標籤(例:「本週」)+ 日期範圍;`日/週/月` 切換器;上/下一期;**排序控制**(`時間` / `按興趣`)。**無計數。**
- **主體** —— 每個來源一個區塊,依當前排序:
  - **來源標頭**:favicon/首字 + 來源名稱(無計數)。
  - 該來源**未讀**文章的**卡片網格**。卡片 = 標題、摘要摘錄(2 行截斷)、時間戳(`M/D HH:mm`),以及動作 **隱藏**(`eye-off` 圖示 —— 刻意不用倒讚;它是把內容從視線移走,而非「評分」)與**儲存**(書籤 → `read_later`)。
  - **「看過的」**折疊切換(無數字),收納該來源的已讀文章。
- **所有來源都在捲動裡渲染** —— 沒有「+N 個來源」的折疊。
- **被隱藏的文章**離開網格,改以一條可撤銷的細線取代(「已隱藏 ·「標題」· 撤銷」);隱藏狀態在重新整理後仍保留。

## 排序與偏好評分(v1)

- **排序控制是非破壞性的。** 它只重排,絕不隱藏或過濾。因為「時間」是預設、「按興趣」一鍵可還原,評分不準也永遠擋不住閱讀 —— 最壞只是順序不理想,每一篇仍在。
- **各模式做什麼**(兩種模式都保留來源分組 + 卡片):
  - `時間`(預設):來源內文章由新到舊;來源依「最近有未讀」排。
  - `按興趣`:來源內文章依偏好評分排(可能是好內容的優先);來源區塊依整體親和度排(你偏愛的來源上浮)。
- **訊號 → 評分**:正向 = 讀(尤其深入閱讀)+ 儲存(`read_later`);負向 = 隱藏(`is_hidden`)。它們維護一個逐使用者的**偏好向量**;某篇的評分 = 其 **embedding**(既有 `EmbeddingService`)與該向量的相似度。
- **冷啟動 / 優雅降級**:訊號很少或沒有時,「按興趣」退回時間序,和/或一個透明的**來源親和度**啟發式(你每個來源的讀/隱比例,累積得很快)。由於「時間」是預設,第一天的空模型永不擋住視圖。
- **可選透明度**:可顯示一個輕量的「為什麼靠前」提示(例:常讀此源 / 與你讀過的相似)。錦上添花,非必要。

## 月視圖細節

- 同一個元件與版面;範圍 = 整個月;**所有未讀攤開**。
- 除了已讀下沉、隱藏與可選排序,不另設密度機制 —— 看到每一篇未讀正是本意。資料量在**抓取**層處理(見「效能」),不是把 UI 藏在點擊後。

## 互動與狀態

- **隱藏(不感興趣)** —— 設定逐 `(使用者, 文章)` 的**隱藏**狀態;該篇立即離開未讀網格;**撤銷**可還原;同時作為評分的負向訊號。v1:不自動隱藏類似內容。**隱藏 = 到處都隱藏**(週、月、每日),以求一致 —— 於計畫中確認。
- **儲存** —— 切換既有 `read_later`;正向訊號。
- **閱讀 / 興趣** —— 打開即標記已讀(複用 Digest 自動標記已讀);沉入「看過的」;正向訊號。不設顯式控制。

## 資料模型與 API

- **新的逐篇使用者狀態:`is_hidden`**(暫定名;備選 `not_interested`)—— 與 `is_read` / `read_later` 並列的布林值。需要:Alembic 遷移、文章服務過濾(未讀查詢排除隱藏)、API 欄位 + 切換端點(比照 `read_later`)、`@glean/types` + `@glean/api-client` + hook 新增。
- **偏好評分(復活,最小)** —— 復活一個最小的 `user_preference_vectors`(逐使用者向量)與逐篇 `preference_score`(存在 `user_entries` 或讀取時計算),**僅**用來排「按興趣」。一個 worker 任務從累積的讀/儲存/隱藏訊號更新使用者向量,並對範圍內文章評分。複用既有文章 embedding。(先前形態見 M3 遷移 `28d8c85cf1a4_m3_preference_system` 與後來的移除 `b6c7d8e9f0a1_remove_reader_mode_preference_storage`。)
- **文章列表查詢** —— 列表服務已支援 `collected_after` / `collected_before` 與 `page` / `per_page`。擴充用法以:抓取週/月範圍、**排除隱藏**、支援**未讀與已讀分流**(已讀延遲抓取給「看過的」)、對大月份**分頁**,並回傳/接受排序。

## 效能 / 大資料量

一個月的未讀可能有數百到數千篇。策略:

- 範圍**未讀**透過分頁請求抓取(既有 `page`/`per_page`),**捲動時自動追加**(無限捲動,不需點擊),讓首屏快速繪製。這純粹是抓取最佳化 —— 每一篇未讀仍靠捲動就出現;分頁絕不是手動的「顯示更多」。
- 在 worker 端**預先計算** `preference_score`,讓「按興趣」排序是一次便宜的有序讀取,而非請求時的向量計算。
- 每個來源的「看過的」(已讀)抓取**延遲到盒子被打開**時。
- 若單一來源的未讀量非常大,加上**列表虛擬化**(於計畫中標記)。
- 複用既有的**伺服器日界 / 時區**邏輯,確保期間邊界一致。

## 邊界情況

- **空期間**(無未讀):友善的空狀態;提供打開「看過的」或跳到上一期。
- **只有已讀/隱藏文章的來源**:不出現在未讀流;僅能透過「看過的」抵達。
- **尚無偏好訊號**:「按興趣」依上述冷啟動規則行為。
- **撤銷時效**:行內的「已隱藏 · 撤銷」細線保留;被隱藏的文章也必須日後仍可還原(一個「隱藏的」入口)—— 確切形式於計畫中決定。
- **翻譯**:卡片標題/摘要遵循既有的列表翻譯設定。

## 待解問題(於實作計畫中決定)

- 「看過的」盒子的範圍:**每個來源一個**(建議)還是全域一個。
- 隱藏狀態命名(`is_hidden` vs `not_interested`);確認**全域隱藏**還是僅限週/月。
- 第三種**跨來源的扁平「重點」排序模式**(不分來源挑最好的)—— 要不要納入,還是延後?
- 偏好向量的重算頻率(每筆訊號 / 批次 / 排程),以及確切的冷啟動混合(純時間 vs 來源親和度)。
- 撤銷時效 + 一個專門檢視/還原隱藏文章的入口。
- 月視圖的次級導覽:無 / 純捲動(建議)還是一條可選的「跳到某週」橫條。
- 分頁的每頁大小,以及虛擬化的門檻。

## 範圍之外(YAGNI)

在這些視圖中做 AI/LLM 摘要或主題聚類;用模型輸出去隱藏或過濾(模型只能排序);自動隱藏類似內容或關鍵字靜音;未讀計數與進度 UI;任何對每日視圖的更動。
