# Summary code purge contract

## Goal

Remove the remaining AI summary implementation and dedicated design/code-example files following the user's explicit request that no feature code remain.

## Scope

- Remove the retained summary ORM module and package export. The latest user request supersedes the previous decision to retain this implementation.
- Remove dedicated obsolete summary/supplement design and implementation documents, and repair their links/index entries. Keep concise deletion records and regression checks rather than executable design examples.
- Remove generated bytecode/build output that still contains deleted feature modules or symbols, limited to known summary artifacts and rebuildable frontend bundles.
- The user explicitly selected removal of the implementation and obsolete design documents while preserving historical migration records. Keep historical Alembic revisions and their operations unchanged.
- Do not delete or modify data in a running database. Preserve translation, RSS article excerpts, embeddings, current reader changes and the MTran fix.

## Done means

- Runtime database metadata contains no summary table/model or export; application imports and retired-route checks pass.
- No remaining feature implementation, dedicated prompt/client/config/UI/SDK, or obsolete implementation examples remain in the source tree.
- Remaining matches, if any, are individually classified as database migration history, deletion regressions or concise audit records, not working feature code.
- Migration history still has a valid single head and no missing parents.
- Generator handoff and independent evaluator assessment record verification and migration scope.

## Verification

- Demonstrate RED then GREEN for clean runtime database metadata.
- Run relevant backend import/API/model/translation tests and targeted lint.
- Verify repository docs references and Git whitespace checks.
- Inspect frontend regenerated bundles for obsolete feature symbols; avoid changing reader source unnecessarily.
